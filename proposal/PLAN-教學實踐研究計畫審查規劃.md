# 教學實踐研究計畫「預審」接入規劃

## 一、定位

把現有的「多模型審查與修訂迴圈」擴充一個新類型：**教學實踐研究計畫書預審**（`paper_type = teaching_practice_proposal`）。

- **目的**：送件前降低「可避免的失分」。不預測是否通過（歷年通過率約 42–48%，官方只公布評分結構，未公布各小項配分）。
- **輸入**：計畫書（必要）、授課計畫書（建議）、歷年自己的計畫書（選用）。
- **輸出**：入口檢查結果、七面向分數、按嚴重度排序的修改清單、依官方體例排版的修訂稿 Word。

## 二、依據（已蒐集）

| 類別 | 內容 | 用在哪裡 |
|---|---|---|
| 官方徵件說明（115 年度附件 1） | 章節與順序、頁數（一年期 ≤ 25，主持人部分 ≤ 5）、體例（標楷體／TNR 12 pt、單行、邊界 2 cm、頁碼置中）、AI 使用聲明、倫理判定、授課計畫書格式 | 入口檢查、版面規格、G 面向 |
| 官方審查評分項目表（113.10.29 修訂） | 主持人部分 20%、執行內容 80%（八個子項）；人力經費與倫理不計分 | 面向與權重 |
| 評審與通過者分享 | 問題意識、問題→策略→評量的對應、延續與創新、評審調閱歷年計畫、多元評量、工具信效度、避免空泛的教學描述 | 檢查項與審查者提示詞 |
| 你的歷年計畫書與授課計畫書（111–115） | 結構、慣用寫法、常見風險（見下節） | 程式檢查的設計與驗證 |

## 三、與期刊審查的差異

| 項目 | 期刊論文審查 | 計畫書預審 |
|---|---|---|
| 對象 | 已完成的研究 | 尚未執行的研究設計 |
| 核心問題 | 證據是否支持結論 | **問題意識是否扎實；問題 × 策略 × 工具 × 分析是否一一對應** |
| 面向 | A–G 通用 | A–G 重新定義（見審查標準第一節） |
| 硬性條件 | 期刊稿約 | **入口檢查 G1–G9（超頁即不審）** |
| 跨文件 | 無 | **計畫書 × 授課計畫書一致** |
| 歷史比對 | 無 | **與歷年計畫書的逐字重複（自我抄襲風險）** |
| 修稿限制 | 不改數據與結論 | **不杜撰教學經歷、學生數據、樣本、評量結果、前期成果** |
| 通過條件 | 連續達標 | 預審只輸出「可送件度」，不做通過預測 |

## 四、架構

```
計畫書 PDF ┐
授課計畫書 ├→ 程式檢查（proposal_checks.py，不靠模型）
歷年計畫書 ┘      頁數／章節／一致性／歷年重複／引註／合規／用詞
                    │（事實依據，審查者不得推翻）
                    ▼
        審查A（教學與研究設計：A C D E）
        審查B（文獻、主持人部分、格式合規：B F G）
                    ▼
        程式判斷停止（沿用既有 code 1，已加入計畫書權重與主責分工）
                    ▼
        修稿者（skill：tp-proposal-reviser）→ 解析 → 下一輪
                    ▼
        終審意見（可送件度＋修改優先順序）→ 報告
                    ▼
        修訂稿 Word（官方體例 layout-spec-moe-proposal.json）
```

## 七、階段 3（之後）

- **成果報告（結案）模式**：雙文件輸入，對照原計畫書，檢查「預期成果」是否兌現、研究問題是否回答、與原設計的偏離是否交代。
- **歷年資料庫**：把你的歷年計畫書建成比對庫，每次自動比對。
- **審查意見回饋**：官方審查意見公布後貼回系統，歸納「哪些項目被扣分」，回頭修正本審查標準的權重。這是校準預審最有效的資料。

## 八、需要你決定的事

1. **要預審的是什麼？** 116 年度新計畫（徵件約在今年 11–12 月）、115 年度的成果報告，還是兩者？這決定先做階段 2 還是階段 3。
2. **接線方式**：2a（本機先跑、貼結果）還是 2b（全部在 Dify）。我建議先 2a，一週內可用；2b 需要把頁數問題處理好。
3. **歷年比對庫**：你願意提供哪幾年的計畫書與授課計畫書作為比對基準？（目前已有 111–115）
4. **審查意見**：你有沒有歷年官方審查意見（通過或未通過者都可）？有的話，我用它校準權重與「常見扣分」清單，品質會明顯提升。

## 九、風險與限制

- 官方沒有公布執行內容各小項的配分，本系統的權重是**預審估計**。
- 模型**無法外部查證文獻**；引註檢查只核對內部一致，結果是候選清單，需人工確認。
- 計畫書若含學生資料，須先**去識別化**再上傳到任何模型（官方要求）。
- 官方規定申請人須在執行期間**實際主授**計畫配合課程；請把你 2026–2027 的研究休假與申請年度的執行期間（8 月至隔年 7 月）對齊確認。
- 若由不同學門、專案（USR、技術實作、情緒健康與福祉）申請，另有增敘項目，需要加模組。

## 十、使用方式（階段 2 完成後）

1. 匯入 `dify/journal-review-loop.yml`（共 30 個節點）。
2. 開始表單：**論文類型選 `teaching_practice_proposal`**；貼上或上傳計畫書；授課計畫書貼上或上傳；選填總頁數與主持人部分頁數、姓名、本機檢查結果。
3. 建議先在本機跑 `proposal/tools/proposal_checks.py`（可讀 PDF 與 Word），把結果貼到「本機檢查結果」欄位：**頁數與歷年重複比對只有本機能做**。
4. 其餘期刊類型的行為與先前完全相同（已以程式驗證：審查者提示、審查標準、修稿規則、版面皆逐字相同）。
5. 實測時請重新確認：Claude 修稿與終審節點關閉思考；「上傳了授課計畫書？」節點的條件（檔案存在）在你的 Dify 版本可正常選取。
